Code Sandbox

A library of guided tech learning workshops. Every one of them runs in a browser, ends in something that works, and stays here after the session is over.

Nothing in here is a lecture. A workshop is a deck you can present and a handful of project folders that already run — one per pass, each one small enough to read in a sitting. No install, no npm, no accounts: if you can open this page you can do the work. Walk out with the thing built.

The shelf

 

How every workshop is built

Same three passes at the same artifact, every time. People quit this subject when night one is forty new words and a blank file. They don't quit when they watched it work first.

Pass 1

I do

Hands off keyboards. Typing along means debugging instead of watching. The instructor builds the smallest version that works.

Pass 2

We do

Keyboards up, nobody types ahead. A checkpoint after every step — “you should see this. Thumbs up.”

Pass 3

You do

Three TODOs in a file that already runs. An answer key exists, and looking at it is allowed. Saying STUCK out loud is encouraged.

The playground

A workshop is a handful of project folders. Each one is an index.html and a js/main.js that opens and runs on its own — no server, no build step, nothing installed. The playground puts those folders in a tree with an editor and a live preview, so you can run them and take them apart without leaving the browser. Click the red live editor chip on any card above.

Every run rebuilds the preview from scratch, so nobody debugs state left over from the last attempt. Errors land in the console in red, with the line number counted from line 1 of the file you are editing. Your edits are kept per file, so a refresh costs nothing — and Reset all puts everything back.

Every js/main.js ends with a short BREAK IT ON PURPOSE list: a few things to change, and what each one teaches when it goes wrong. Delete an await and you get [object Promise] — you printed the waiting instead of the thing. That is a better lesson than a paragraph about promises, and it costs one keystroke.

Add the next workshop

Fifteen minutes of setup, then you're writing content. The template is a working workshop with the words taken out — it opens and runs before you change a thing.

  1. Copy workshops/_template/ to workshops/0N-your-slug/. Numbers are shelf order, not week order.
  2. Rewrite REF-deck.html. Arrow keys drive it, Ctrl+P saves it as a PDF. Do not touch the <style> block — the palette is the house palette.
  3. Fill in the project folders under projects/ — one per pass, each an index.html and a js/main.js. Leave exactly three TODOs in the You do one, and make sure it still runs with all three unfinished.
  4. Write the answer key folder. If you can't finish your own TODOs in nine minutes, they're too big.
  5. End each js/main.js with a BREAK IT ON PURPOSE list.
  6. Run python tools/build-playground.py. It reads your projects/ folders and writes playground.html — nothing to maintain by hand.
  7. Add one object to js/workshops.js, with live: true. The card and the live editor chip build themselves.
  8. Teach it to real people, then change status to "ready". That word means survived a cohort, not finished writing.

Full checklist in CONTRIBUTING.md, including the parts of the house style that are not up for redesign.
