Code Sandbox

A library of guided tech learning workshops. Every one of them runs in a browser, ends in something that works, and stays here after the session is over.

Nothing in here is a lecture. Each workshop is a deck you can present, a live editor you can type into, and a finished build to compare yours against. No install, no npm, no accounts — if you can open this page you can do the work. Walk out with the thing built.

The shelf

 

How every workshop is built

Same three passes at the same artifact, every time. People quit this subject when night one is forty new words and a blank file. They don't quit when they watched it work first.

Pass 1

I do

Hands off keyboards. Typing along means debugging instead of watching. The instructor builds the smallest version that works.

Pass 2

We do

Keyboards up, nobody types ahead. A checkpoint after every step — “you should see this. Thumbs up.”

Pass 3

You do

Three TODOs in a file that already runs. An answer key exists, and looking at it is allowed. Saying STUCK out loud is encouraged.

Two ways to write the code

Nobody installs anything to do a workshop here. Every step page carries a sandbox — one file, with the blanks still in it. And every workshop has a playground: the whole file tree, already working, for taking apart. Click the red live editor chip on any card above to open one. Your work is kept in the browser, so a refresh doesn't cost you anything.

On a step page

The sandbox

One file, one job. The blanks are where the lesson is. Run rebuilds the preview from scratch, so you never debug leftovers.

Per workshop

The playground

Folders down the left. Click one and it runs; click a file and it opens. Delete a line, press Run, see what broke. Reset all undoes everything.

Always

Real files too

The same code sits on disk in each workshop's js/. The point is to end up editing real files — the editors just buy back night one.

The playground is what "break it and play with it" looks like when nothing can actually break: it runs in your browser, nobody else sees it, and one button puts it all back.

Add the next workshop

Fifteen minutes of setup, then you're writing content. The template is a working workshop with the words taken out — it opens and runs before you change a thing.

  1. Copy workshops/_template/ to workshops/0N-your-slug/. Numbers are shelf order, not week order.
  2. Rewrite REF-deck.html. Arrow keys drive it, Ctrl+P saves it as a PDF. Do not touch the <style> block — the palette is the house palette.
  3. Fill in the three step pages. Each one is a sandbox: a block of starter code and a block of answer code, as plain text. Leave exactly three TODOs in the You do step.
  4. Write the answer key. If you can't finish your own TODOs in nine minutes, they're too big.
  5. Run python tools/build-playground.py. It reads your step pages and writes playground.html for you — nothing to maintain by hand.
  6. Add one object to js/workshops.js, with live: true. The card and the live editor chip build themselves.
  7. Teach it to real people, then change status to "ready". That word means survived a cohort, not finished writing.

Full checklist in CONTRIBUTING.md, including the parts of the house style that are not up for redesign.

The source tree

Plain static site. Pages are HTML, styles are CSS, scripts are JS, and the whole thing is served straight off GitHub Pages. There is no build step to break.
