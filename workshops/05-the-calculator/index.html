The Calculator

Three functions, eleven lines, one calculator. Numbers go in, an answer comes out — until you ask it to divide by zero, and then it has to decide what an honest function does when it cannot do its job.

1 · The calculator

It works. Change the numbers, press a button. Then make the second number 0 and press ÷.

2 · What a function actually is

A machine with four parts. That is the whole idea, and every function you will ever write — in any language — has these same four:

function add(a, b) { return a + b; } │ │ │ │ │ │ │ └─ return │ │ └─── body │ └───────── inputs └───────────── name
  1. name — so something else can call it
  2. inputs — what it needs in order to work. Also called parameters, or arguments when you are talking about the actual values you hand over.
  3. body — the work. Everything between the { }.
  4. return — the answer it hands back

Call it and the answer comes back: add(2, 3) is 5. The two numbers you hand it are the inputs. The 5 is the return value. You write the machine once and press the button a thousand times.

Leave off the return and the function still runs perfectly. It just hands back nothing — and whatever called it gets undefined. That is the most common bug in this whole workshop, and the BREAK IT list at the bottom of js/main.js makes you cause it on purpose.

3 · Three functions, one shape

Here is all of js/lib/math.js. Same four parts every time — only the body changes:

NameBodyWorks for any two numbers?
add return a + b; Yes.
subtract return a - b; Yes — but the order matters. subtract(3, 10) is -7, not 7.
divide if (b === 0) return null;
return a / b;		 No. Which is why it has an extra line.
4 · The function that cannot always answer

Dividing by zero has no answer. Not a big answer, not zero — no answer at all. So divide has to decide what to do when it cannot do its job, and it has three choices:

It could…Screen showsWhy that is a problem
return 0 0 A lie that looks true. 10 ÷ 0 is not 0. Now a wrong number is loose in the program with nothing marking it as wrong, and anyone who reads it will believe it.
nothing — let JavaScript answer Infinity Honest, and useless on a screen. It is also sticky: add anything to Infinity and you still get Infinity, so one bad divide spreads into every sum after it.
return null — what it does no answer Nothing. null means “no answer”, and whoever called the function now has to deal with that out loud.

A function that admits it has no answer is worth more than one that invents a believable number. Same rule as workshop 03's panel that refuses questions it cannot trace, and the same rule as week 8's not built yet — say where you stop.

So who deals with it? js/components/Readout.js, in three lines: it checks answer === null and prints no answer — you cannot divide by zero. The function decided it could not answer; the screen decided how to say so. Two jobs, two files.

5 · Where the files live, and why
  • js/lib/math.js The three functions. No React, no buttons, no HTML — it draws nothing at all. Work goes in lib/.
  • js/components/Readout.js Shows the answer, or says there is not one. Does no arithmetic.
  • js/components/Calculator.js The screen: two inputs, three buttons. Screens go in components/. It does not know how to add — it only knows which function to call.
  • js/main.js Puts the calculator on the page, runs the table below, and ends with the BREAK IT list.
