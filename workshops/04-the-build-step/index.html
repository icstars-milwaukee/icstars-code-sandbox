The Build Step

JSX is not JavaScript. No browser has ever understood it — something has to translate it first, and that something is why a React project needs npm install, a package.json and Vite. You will build a profile card, watch the translation happen, take the card apart into components, and then install a project of your own.

1 · Watch the translation

A profile card, in three components. Left is what you write. Middle is what actually runs. Right is the card itself. Edit the left and the other two keep up. This is the entire job of the build step — there is no magic under it.

    3 · Where the files go

    
    
      This is a Vite React project with those components in it. Nothing here is
      convention-for-its-own-sake — each folder answers one question.
    
    


    my-app/
├── index.html              the ONE page the browser loads. React fills the div in it.
├── package.json            the shopping list: what to install, what to run
├── vite.config.js          tells Vite to expect React
│
├── src/                    everything you write lives here
│   ├── main.jsx            the plug: finds that div, renders <App /> into it
│   ├── App.jsx             the top of YOUR app. Decides what pages exist.
│   │
│   ├── components/         the boxes. One component, one file, named for itself.
│   │   ├── Profile.jsx
│   │   ├── Avatar.jsx
│   │   ├── Stat.jsx
│   │   └── Badge.jsx
│   │
│   ├── lib/                code that is NOT a screen: fetching, maths, dates
│   │   └── api.js
│   │
│   └── styles.css          colours and spacing
│
└── node_modules/           the groceries. Never opened, never committed.
    

    
    
      The two rules that matter and the one that does not:
    
    

    
      
      
    • One component, one file, named the same as the component.
        Avatar.jsx exports Avatar. When a number on screen is
        wrong, you know which file to open without searching.
      • 
      
    • components/ draws screens. lib/ does not.
        Fetching, formatting and maths go in lib/. Keeping them apart is what
        lets you fix a query without touching a single component.
      • 
      
    • Folder names are not law. Some teams use
        ui/, some nest by feature. Any arrangement where "where do I change
        this?" has one obvious answer is a good one. Pick it on day one and keep it.
      • 
    
    

    
    4 · What npm install is for

    
    
      
        
    The thingIts one job
    
          
      
        
    
          package.json
          The shopping list. Names every package your project needs, and
          the commands you can run. Checked into Git; small; you read it.
        
    
        
    
          package-lock.json
          The receipt. The exact version of every package, including the
          packages your packages wanted. Checked in so your laptop and CodeSandbox install
          the identical thing. Never edited by hand.
        
    
        
    
          node_modules/
          The groceries. The actual downloaded code — thousands of
          files, tens of megabytes. Never committed, because
          npm install recreates it from the two files above.
        
    
        
    
          vite.config.js
          The kitchen. Tells Vite to expect React, so it runs that JSX
          translation on every file as you save it.
        
    
        
    
          dependencies
    devDependencies    		
          Ships vs. builds. react is a dependency — it
          runs in the user's browser. vite is a devDependency — it builds
          the thing and is never sent to anyone. Backwards ships a toolchain to your users.
