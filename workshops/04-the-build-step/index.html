The Build Step

Three stages, and each one is the stage before it plus one new idea: Hello World → Profile → Data. By the end you will have written React, seen what the computer turns it into, and drawn a graph from real API numbers.

The editor

Pick a stage. You write the left. The computer turns it into the middle. The middle is what draws the right. Change the left and watch both follow. 


      

      

        
        

        

      

    


    

      
    


    
    Stage 1 · Hello World

    

      Click 1 · Hello World above. Two lines. Look at all three columns.
    


    
    
      
  1. You wrote a tag. <h1>Hello, world</h1> looks like
        HTML, but it is sitting inside JavaScript. Mixing the two like this is called
        JSX.
    2. 

      
  2. No browser understands JSX. Not one, not ever. So something has to
        rewrite it first.
    3. 

      
  3. Look at the middle column. Your tag became
        React.createElement("h1", null, "Hello, world") — an ordinary function
        call. That is all a tag ever was.
    4. 

      
  4. That rewrite is the build step. It is the whole reason a React project
        needs installing. Vite is the tool that does it for you, every time you
        save.
    5. 
    


    

      Try it: delete the </h1>. The middle column turns into an error message
      with a line number, and nothing draws. That is the build step telling you it cannot finish.
    


    
    Stage 2 · Profile

    

      Click 2 · Profile. Same idea, bigger: a profile card.
    


    
    
      
  1. A component is a box you named. That is all. You drew a box round
        part of the page, gave it a name, and now you can use it again.
    2. 

      
  2. Boxes go inside boxes. The card holds an Avatar and three
        Stats. Stat exists because the card needed three of them —
        that is the only good reason to make one.
    3. 

      
  3. Props are what you put in the box.
        <Stat label="commits" value={48} /> — same box, different contents.
        The box decides how it looks; whoever uses it decides what goes in.
    4. 

      
  4. A capital letter means your box. <Avatar /> is yours.
        <div /> is an HTML tag. That is the entire rule.
    5. 
    


    

      Here is the finished card. Hover a row to find that box on the card.
    


    

      
    
      
    
    
    

    
    Stage 3 · Data

    
    
      The profile card had its numbers typed into it. Real numbers do not work like that —
      they live somewhere else, and you have to go and ask.
    
    

    
      
      
    1. An API is a window you ask questions through. You pass a question in.
        It passes an answer back. You never go inside.
      2. 

      
    2. Our API is one window at
        c21-data-gateway. You send it a question written in SQL and it sends back
        the rows. That is the whole arrangement.
      3. 

      
    3. The answer comes back as JSON — a way of writing down data so a
        program can read it. Two parts matter: columns (what each slot means) and
        rows (the slots).
      4. 

      
    4. A graph is just those rows, drawn. No new data appears when you make a
        chart. Every bar is one row.
      5.

    Where the files go

    
      
      A real Vite React project, with those boxes in it. Each folder answers one question.
    
      


      my-app/
├── index.html              the ONE page the browser loads
├── package.json            the shopping list: what to install, what to run
│
├── src/                    everything YOU write lives here
│   ├── main.jsx            the plug: puts <App /> on the page
│   ├── App.jsx             the top of your app
│   │
│   ├── components/         your boxes. One box, one file, named the same.
│   │   ├── Avatar.jsx
│   │   ├── Stat.jsx
│   │   └── Bar.jsx
│   │
│   └── lib/                code that is NOT a box: asking the API, maths
│       └── api.js
│
└── node_modules/           the downloaded code. Never opened, never committed.
      

    
      
      This workshop is built that way too. Not as an example in a
      box — the page you are reading is ten files in those folders.
      Open the live editor and the sidebar shows you
      js/api/, js/components/ and js/lib/,
      one thing in each file. Open js/components/Stat.js and that is
      the whole of Stat, fourteen lines including the comment.
    
      

    
        
      
      • One box, one file, same name. Avatar.jsx holds
        Avatar. When something looks wrong you know which file to open.
        • 
      
      • components/ draws. lib/ fetches. Asking the
        API goes in lib/. That split is what lets you fix a question without
        touching a single box.
        • 
      
      • Folder names are not law. Any layout where
        "where do I change this?" has one obvious answer is a good one. Pick it and keep it.
        •
