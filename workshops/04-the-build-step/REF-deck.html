You will walk out with a React app running on your own machine, three screens in it, and a straight answer to the question nobody ever answers: why does this need installing at all?

JSX is not
JavaScript

No browser has ever understood it. Not one, not ever.

So something has to rewrite it first. That something is the build step, and it is the whole reason a React project has a package.json.

Four words

Four words

WordWhat it means
JSXHTML-looking code written inside JavaScript. What you type.
ComponentA box you drew round part of a page and gave a name.

ViteThe tool that does the rewriting, every time you save.
Stage 1 · I do

One tag in.
One function call out.

src/pages/HelloPage.jsx — what I write: export default function HelloPage() { return <h1>Hello, world</h1>; } What the browser actually runs: function HelloPage() { return React.createElement("h1", null, "Hello, world"); }

I say: "That is the entire job. A tag was always a function call wearing a costume. Vite takes the costume off on the way to the browser - and that is the only thing it has done so far."

Stage 1 · the same thing, Vite's way

And with the
modern setting

The same file, compiled the way Vite does it by default: import { jsx as _jsx } from "react/jsx-runtime"; function HelloPage() { return _jsx("h1", { children: "Hello, world" }); }

Notice the import that you did not type. That line is what people mean when they say the build step "adds things" - and it is why a modern React file no longer starts with import React from "react".

I DO → WE DO
→ YOU DO

Watch stage 1. Then we open it together and change one thing. Then you build stages 2 and 3 in your own folder.

Stage 2 · components

A component is
a box you named

src/components/Stat.jsx — the whole file: export default function Stat({ label, value }) { return ( <div className="stat"> <b>{value}</b> <span>{label}</span> </div> ); }

I say: "Nine lines. It exists because the profile needed three of them - repetition, not tidiness, is what earns a component its own file."

Stage 2 · props

Props are what
you put in the box

src/pages/ProfilePage.jsx — the page uses Stat three times: <Stat label="commits" value={48} /> <Stat label="PRs" value={7} /> <Stat label="weeks" value={8} />

Same box, different contents. The component decides how it looks. Whoever uses it decides what goes in it. That split is the first real habit of this job.

And a capital letter means your box. <Stat /> is yours; <div /> is an HTML tag. That is the whole rule.

An API is a window
you ask questions through

You pass a question in. It passes an answer back. You never go inside.

Ours is one window at c21-data-gateway. You send it SQL; it sends back rows.

Stage 3 · the question and the answer

Ask, and look at
what comes back

You send: POST /api/query { "team": "...", "sql": "SELECT ... GROUP BY ..." } It sends back: { "columns": ["team", "open_tickets"], "rows": [ ["Service Desk", 57], ["Network", 44], ["Cloud Platform", 41] ], "rowCount": 6 }

Two parts matter. columns says what each slot means. rows is the slots. That is the whole format.

Stage 3 · the graph

A graph is just
those rows, drawn

src/pages/DataPage.jsx — one Bar per row: {reply.rows.map((row) => ( <Bar key={row[0]} name={row[0]} value={row[1]} most={most} /> ))}

No new information appears when you make a chart. Six rows in, six bars out. If a number looks wrong on a graph, the graph is almost never where it went wrong.

One colour for every bar, on purpose: the length already tells you which is biggest, so colour stays free for a different job.

You do · the folders

Where things live

src/ main.jsx the plug. Puts <App /> on the page. App.jsx which screen you are looking at pages/ a whole screen you could navigate to components/ a part you use on more than one screen api/ data and fetching. NOT a screen. styles.css

Two rules that matter: one component, one file, named the same. And components/ draws while api/ fetches - so you can fix a query without opening a single screen.

Folder names are not law. Any layout where "where do I change this?" has one obvious answer is a good one.

You do · until the end

Install one,
from nothing

node -v v18 or newer, or nothing works npm create vite@latest my-app -- --template react cd my-app && npm install node_modules appears. It is huge. npm run dev localhost:5173, and it stays running

Then change a word in src/App.jsx and save. You did not reload anything. That is the dev server doing the rewrite again, in the time it took you to lift your finger.

No laptop set up? Open the finished one in the browser: change github.com to githubbox.com on any GitHub folder and it becomes a running CodeSandbox. That trick works on anybody's repo.

Stuck more than 15 minutes? Say so out loud. That is the rule, not a last resort.
